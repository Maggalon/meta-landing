# Заявки МЕТА → Google Таблица

В проекте подготовлена цепочка: форма → `/api/contact` на сервере сайта → Google Apps Script → закрытая Google Таблица. Посетитель не получает адрес скрипта или секретный токен. Сообщение об успехе появляется после подтверждения записи в таблицу.

Google-аккаунт пока не подключён. Для запуска нужно выполнить настройку ниже; затем проверить реальную доставку тестовой заявки. Код и локальные проверки не заменяют эту проверку.

## 1. Подготовить таблицу и скрипт

1. В своём Google-аккаунте создайте пустую таблицу **«МЕТА — заявки»**. Общий доступ оставьте **«Ограниченный»**.
2. В таблице откройте **Расширения → Apps Script**.
3. Замените содержимое `Code.gs` кодом из [integrations/google-sheets/Code.gs](../integrations/google-sheets/Code.gs).
4. В настройках проекта включите отображение файла `appsscript.json`. Замените его содержимое файлом [appsscript.json](../integrations/google-sheets/appsscript.json). Он использует V8 и доступ к Google Таблицам.
5. Сохраните проект. Выберите функцию **setup** и нажмите **Выполнить**. При первом запуске Google запросит разрешение скрипту работать с таблицами от вашего имени.
6. Вернитесь в таблицу: появится лист **«Заявки»** с заголовками, фильтром и списком статусов. Повторный запуск `setup` не удаляет заявки и не меняет существующий секрет.

Скрипт работает только с ID таблицы, записанным при настройке. Не меняйте порядок и названия столбцов листа «Заявки»: если схема нарушена, запись остановится с ошибкой. Дополнительные отчёты можно делать на отдельных листах.

## 2. Получить секрет и адрес обработчика

1. В Apps Script откройте **Настройки проекта → Свойства скрипта**. После `setup` там будут:
   - `SPREADSHEET_ID` — ID вашей таблицы;
   - `SHEET_NAME` — `Заявки`;
   - `WEBHOOK_TOKEN` — сгенерированный секрет для сайта.
2. Скопируйте значение `WEBHOOK_TOKEN` в серверную переменную `CONTACT_WEBHOOK_TOKEN` (см. следующий раздел). Секрет не нужно присылать в чат или вставлять в исходный код.
3. Выберите **Развернуть → Новое развертывание → Веб-приложение**.
4. **Выполнять от имени:** вашего аккаунта. **У кого есть доступ:** «Все» / «Anyone», включая посетителей без входа в Google. Если организация запрещает такой режим, этот способ подключения потребует разрешения администратора.
5. Нажмите **Развернуть** и скопируйте URL вида `https://script.google.com/macros/s/…/exec`. Нужен адрес `/exec`, не тестовый `/dev`.

Публичным становится только вход обработчика. Сама таблица остаётся закрытой; записывать данные обработчик позволяет только с секретом. GET-запрос возвращает состояние сервиса, без заявок и без секретов.

При последующих изменениях `Code.gs` обновляйте развертывание: **Управление развертываниями → Изменить → Новая версия → Развернуть**. Простое сохранение кода не обновляет уже опубликованную версию.

## 3. Настроить сайт

Локально добавьте значения в `.env.local`. На VPS — в `.env` рядом с `compose.production.yaml`. Если файл уже есть, добавьте переменные, сохранив остальные настройки.

```dotenv
CONTACT_WEBHOOK_PROVIDER=google-sheets
CONTACT_WEBHOOK_URL=https://script.google.com/macros/s/ВАШ_ID_РАЗВЕРТЫВАНИЯ/exec
CONTACT_WEBHOOK_TOKEN=СЕКРЕТ_ИЗ_СВОЙСТВ_СКРИПТА
CONTACT_PRIVACY_URL=
CONTACT_CONSENT_URL=
CONTACT_CONSENT_TEXT=
```

Последние три значения уже требуются существующей формой:

- `CONTACT_PRIVACY_URL` — ссылка на вашу утверждённую политику обработки данных;
- `CONTACT_CONSENT_URL` — ссылка на текст согласия;
- `CONTACT_CONSENT_TEXT` — утверждённая подпись чекбокса согласия.

Ссылки могут быть HTTPS-адресами или существующими страницами этого сайта вида `/privacy`. Произвольные несуществующие пути использовать не нужно. Этот проект не создаёт юридические документы автоматически.

Секрет должен содержать не менее 32 символов; `setup` создаёт 64 символа. Не используйте префикс `NEXT_PUBLIC_`. `.env.local` и `.env` исключены из Git.

Для первого запуска нужно собрать и опубликовать обновлённый код сайта. После настройки окружения перезапустите локальный dev-сервер или пересоздайте контейнер с новым образом:

```bash
docker compose -f compose.production.yaml up -d --force-recreate landing
```

Эта команда использует уже собранный образ `meta-landing:production`; сама по себе она не собирает и не публикует изменения. Для дальнейшей смены только секретов/ссылок сборка не нужна.

Пока обязательные настройки не заполнены, форма сохраняет существующий режим подготовки сообщения в Telegram. После настройки появятся чекбокс согласия и кнопка **«Отправить заявку»**.

## 4. Проверить подключение

1. Откройте URL `/exec`: ожидается JSON с `ok: true`, `service: "meta-applications"`, `version: 1`. Это проверяет доступность скрипта, но ещё не запись в таблицу.
2. Обновите страницу сайта. Заполните форму вымышленными данными: имя **«ТЕСТ — подключение»**, контакт `test@example.invalid`, роль, задачу и комментарий.
3. Отметьте согласие и отправьте. Успех должен появиться только после записи.
4. В листе «Заявки» должна появиться одна строка со статусом **«Новая»**. Проверьте контакт, комментарий и задачу. Для проверки UTM откройте сайт с `?utm_source=integration-test` перед заполнением.
5. Отметьте эту тестовую заявку статусом «Закрыта».

При ошибке заполненные поля остаются в форме. Повтор без изменения полей использует тот же ID; скрипт проверяет его в таблице под блокировкой и не создаёт новую строку. Не удаляйте ID уже принятых заявок. Если вручную удалить всю заявку, её последующая повторная отправка может создать строку снова.

## Что сохраняется

Каждая заявка — одна строка: ID, время поступления (UTC), имя, роль, контакт, задача, класс, комментарий, статус, четыре UTM-метки, время согласия (UTC), текст согласия и ссылки на согласие/политику. Контакты и комментарии записываются как текст, а не формулы. Все цены и состав услуг остаются на сайте; в этом подключении сохраняются поля текущей формы.

Статусы для ручной работы: **Новая → Связались → В работе → Закрыта**. Фильтр и первая закреплённая строка помогают разбирать заявки.

## Проверки и ограничения

```bash
npm run test:contact
npm run lint
npx tsc --noEmit
```

Локальные тесты используют подставной HTTP-клиент и имитацию сервисов Apps Script. Они не обращаются к Google и не отправляют настоящие контакты. Проверяются подтверждение записи, повторные запросы, неверные токены, ошибки хранилища, безопасная обработка редиректов и сохранение формул как текста.

Тайм-аут Google-доставки — 20 секунд, ожидание формы — 25 секунд. После тайм-аута скрипт мог успеть сохранить строку: повтор той же заявки должен подтвердить существующую запись. Автоматической очереди фоновых повторов нет. Прямые обращения по ссылке Telegram не попадают в таблицу.

Google Apps Script имеет [квоты](https://developers.google.com/apps-script/guides/services/quotas). При отказе Google или превышении квот сайт показывает ошибку вместо ложного успеха. Для небольшого потока заявок этот вариант не требует дополнительного сервера автоматизации; при росте нагрузки можно заменить получателя, сохранив `/api/contact`.

Существующая защита сайта: honeypot, проверка origin, лимит тела 16 КБ и 5 попыток за 10 минут на IP в памяти процесса. Reverse proxy должен перезаписывать `X-Forwarded-For`; для нескольких экземпляров приложения нужен общий лимит на proxy.

## Что передать для завершения

- Адрес развернутого скрипта `/exec`.
- Ссылки на политику и согласие, а также подпись чекбокса.
- Где настроены переменные работающего сайта: локально или на VPS. Токен впишите туда самостоятельно либо предоставьте доступ к настройке окружения; пароль от Google не нужен.
- После подключения — проверить тестовую строку в вашей таблице.

Документация Google: [развёртывание веб-приложения](https://developers.google.com/apps-script/guides/web), [редиректы ContentService](https://developers.google.com/apps-script/guides/content#redirects), [свойства скрипта](https://developers.google.com/apps-script/guides/properties), [блокировки](https://developers.google.com/apps-script/reference/lock/lock-service).
